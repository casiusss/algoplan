<objective>
Wave 3 — atomic flip of the `multica://` → `algoplan://` deep-link scheme across BOTH the web→desktop handoff page AND the desktop main process. This is the highest-risk single change in Phase 7: any non-atomic merge breaks the Google OAuth → Desktop login flow for every user mid-update.

Purpose: The deep-link scheme is the contract between two separately-deployed surfaces (web app served from algoplan.ai, desktop app installed locally). The web page emits `algoplan://auth/callback?token=...`, the OS routes it to the registered handler, and the desktop main process parses the URL. If web is updated but desktop is on an old version (or vice versa), the user clicks "Login" on web → nothing happens. Plan 07-03 already flipped `PROTOCOL = "algoplan"` in main; this plan flips the consumer side AND adds the deep-link unit test that locks the contract.

Why a separate plan from 07-03: clarity of review. The diff for this plan is laser-focused: 4-5 line changes per file across 3 production files plus 1 new test file. Reviewers can read the entire delta in one glance and confirm the scheme matches end-to-end.
Output: 4 production files + 2 test files; new deep-link unit test.
</objective>

<interfaces>
<!-- Cross-app deep-link contract -->

Web → OS: web page issues `window.location.href = "algoplan://auth/callback?token=<jwt>"`.
The browser asks the OS to open the URL using the registered handler for `algoplan:` scheme.

OS → Desktop main: macOS dispatches via `app.on("open-url")`; Windows/Linux pass URL as last argv on second-instance.

Desktop main → renderer: `handleDeepLink` parses `parsed.protocol === "algoplan:"`, then routes by hostname:
  - `algoplan://auth/callback?token=<jwt>` → `mainWindow.webContents.send("auth:token", token)`
  - `algoplan://invite/<id>` → `mainWindow.webContents.send("invite:open", id)`

Renderer (App.tsx): `window.desktopAPI.onAuthToken(handler)` listens for "auth:token" IPC events. No scheme strings here — comments only.

Web (login/page.tsx): "Open in Desktop App" button issues `window.location.href = "algoplan://auth/callback?token=<token>"` after the user clicks (alternative path to the auto-redirect in callback/page.tsx).
</interfaces>

  ```typescript
  // Deep-link parsing extracted from index.ts for testability (Phase 7 Plan 07-04).
  // Pure function: takes a URL string + a "send" callback (BrowserWindow.webContents.send),
  // returns void. No side effects beyond the callback.

  const PROTOCOL = "algoplan";

  type SendFn = (channel: string, ...args: unknown[]) => void;

  export function handleDeepLink(url: string, send: SendFn | null): void {
    if (!send) return;
    try {
      const parsed = new URL(url);
      if (parsed.protocol !== `${PROTOCOL}:`) return;

      // algoplan://auth/callback?token=<jwt>
      if (parsed.hostname === "auth" && parsed.pathname === "/callback") {
        const token = parsed.searchParams.get("token");
        if (token) send("auth:token", token);
        return;
      }

      // algoplan://invite/<invitationId>
      if (parsed.hostname === "invite") {
        const id = parsed.pathname.replace(/^\//, "");
        if (id) send("invite:open", decodeURIComponent(id));
        return;
      }
    } catch {
      // Ignore malformed URLs
    }
  }

  export const PROTOCOL_NAME = PROTOCOL;
  ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS → desktop main via deep link | Untrusted URL arrives from any source on the system; must validate strictly |
| web → OS → desktop | OAuth callback hands the user-controlled `token` query param to the desktop; signed by server, but format-validate first |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04-01 | Tampering | handleDeepLink token param | mitigate | URL parser drops malformed URLs; token is server-issued JWT (validated by /auth verify endpoint downstream); no eval, no shell injection paths |
| T-07-04-02 | Spoofing | Legacy multica:// URLs | mitigate | Test-3 in deep-link.test.ts explicitly asserts handleDeepLink REJECTS multica:// — prevents an attacker (or stale browser link) from triggering auth flow under the legacy scheme |
| T-07-04-03 | Denial of Service | Cold-start deep link before window ready | mitigate | Test-8 (null send) verifies handleDeepLink no-ops without throwing; index.ts guards `mainWindow?.webContents?.send.bind(...) ?? null` |
| T-07-04-04 | Elevation of Privilege | OS protocol handler hijacking | accept | Any signed app on the system can claim `algoplan:` scheme; mitigation = code-signed/notarized binaries (existing notarize: true) — same threat as multica:// pre-Phase-7 |
</threat_model>
