## Decisions Made

1. **`pgtype.Text` wrap on the hash arg.** The plan's `<interfaces>` block listed `GetUserByEmailVerifyTokenHash(ctx, hash string)`, but the actual sqlc-generated signature is `pgtype.Text`. Caught on first compile (`cannot use tokenHash (string) as pgtype.Text`). The fix is the standard wrap `pgtype.Text{String: hash, Valid: true}`, identical to Plan 01's `CreateUserWithPassword` call site for the same column.
2. **Constant for the OK message.** Pulled `"If an account exists, a new verification link has been sent."` into `resendEmailVerifyOKMessage` rather than inlining it three times. The plan's pseudocode showed inline `const okMessage` inside the function body — promoting it to package scope makes the contract (same shape across all paths) syntactically obvious.
3. **Backdate-via-helper-arg over schema mutation.** The two failing resend tests needed the seed token to appear issued > 60s ago. The helper already takes `expiresIn` — passing `24*time.Hour - 2*time.Minute` yields the same effect as `INSERT ... THEN UPDATE expires_at = ...` without an extra DB round-trip and keeps the test's intent visible at the call site.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Backdated seed expiry in two RED test fixtures so the W5 rate-limit math accepts the FIRST resend.**
- **Found during:** Task 3 (ResendEmailVerify handler verification step).
- **Issue:** The Plan 00 RED scaffolds for `TestResendEmailVerify_Unverified` and `TestResendEmailVerify_RateLimit` called `verifyUserWithToken(t, email, 24*time.Hour)`, which inserts the seed user with `email_verify_expires_at = now() + 24h`. Under the Plan 02 W5 fix, the handler reconstructs `issuedAt = expires_at - 24h ≈ now()`, then refuses if `time.Since(issuedAt) < 60s`. Result: the FIRST resend in both tests was rate-limited (429) instead of succeeding (200). The plan's Pitfalls §3.3 explicitly anticipated this: *"To exercise the not-rate-limited path, the test should backdate `email_verify_expires_at` ... so the reconstructed `issuedAt` is 2 minutes ago — past the 60s cooldown."* Plan 00's RED scaffolds did not implement that backdating.
- **Fix:** Changed both test calls to `verifyUserWithToken(t, email, 24*time.Hour-2*time.Minute)` and added a comment block in each test explaining the backdating rationale. No production code changed.
- **Files modified:** `server/internal/handler/auth_email_verify_test.go`
- **Verification:** `go test ./internal/handler/ -run 'TestEmailVerify_|TestResendEmailVerify' -count=1` → all 8 green.
- **Committed in:** `b58be521` (Task 3 commit, alongside the handler implementation it unblocks).

**2. [Rule 3 - Blocking] Wrapped the hash string in `pgtype.Text` for the GetUserByEmailVerifyTokenHash call.**
- **Found during:** Task 2 (EmailVerify handler verification step).
- **Issue:** Plan's `<interfaces>` block listed `GetUserByEmailVerifyTokenHash(ctx, hash string)`. Actual sqlc-generated signature is `(ctx, emailVerifyTokenHash pgtype.Text)` — the underlying SQL column is nullable so codegen always uses `pgtype.Text` regardless of caller intent. First build failed with `cannot use tokenHash (variable of type string) as pgtype.Text value in argument`.
- **Fix:** Wrapped: `pgtype.Text{String: tokenHash, Valid: true}`. Identical pattern to Plan 01's `CreateUserWithPassword` call for the same `email_verify_token_hash` column.
- **Files modified:** `server/internal/handler/auth_email_verify.go` (added `pgtype` import + wrapped the call site).
- **Verification:** `go test ./internal/handler/ -run 'TestEmailVerify_' -count=1` → all 4 green.
- **Committed in:** `7f82f04b` (Task 2 commit).
