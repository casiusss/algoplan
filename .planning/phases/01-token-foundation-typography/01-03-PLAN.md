## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inline `<script>` in HTML head | Executes synchronously in renderer context; XSS risk if any user-controlled content reaches the script body |
| localStorage `multica_theme` key | Read/written by both pre-React script and post-mount next-themes; tampering only affects local UI |
| `packages/core/theme/index.ts` re-export | Compile-time forward; no new runtime surface created |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Injection (XSS) | Inline FOUC script in index.html | mitigate | Script body is STATIC string with NO interpolation. The `var t = localStorage.getItem(...)` pulls a string and only branches on equality (`=== 'dark'`, `=== 'system'`); even if localStorage held HTML, it would never be rendered as such. No `innerHTML`, no `eval`, no `document.write`. Reviewer must reject any future PR that interpolates user input into this script. |
| T-01-03-02 | Tampering | localStorage `multica_theme` key | accept | Storage tampering only flips the user's own theme. No privilege boundary crossed. |
| T-01-03-03 | Information Disclosure | Theme preference reveal | accept | Theme is non-sensitive. No PII or auth state stored. |
| T-01-03-04 | Denial of Service | Inline script throws → renderer fails | mitigate | The `try { ... } catch (e) {}` wrapper swallows ALL errors. The script CANNOT block React mount — worst case, theme defaults to light, next-themes recovers post-mount. |
| T-01-03-05 | Elevation of Privilege | Pre-React script execution | accept | The script runs in the same renderer context as React. It manipulates only `document.documentElement.classList`. No DOM injection, no fetch, no eval. |
| T-01-03-06 | Boundary Violation | @multica/core depending on react-dom via theme barrel | mitigate | TypeScript `export { ... } from` is a compile-time symbol forward. Verified by grep — no runtime react-dom import added to packages/core/. The boundary rule (CLAUDE.md) is preserved. Reviewer must reject any future PR adding non-`type` `import` from react/react-dom/next-themes inside `packages/core/`. |
