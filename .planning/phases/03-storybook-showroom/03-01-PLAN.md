<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tailwind `@source` glob → filesystem | Tailwind reads files matching the glob to extract class names; an over-broad glob would scan unrelated files (CPU waste; class-name collision risk if non-React files contain Tailwind-looking strings) |
| `@fontsource-variable/inter` → CSS @font-face | Loads font files from `node_modules`; if the package were compromised, the iframe would load attacker-controlled font files (CSS-side; no JS execution) |
| `@multica/ui/styles/{tokens,base}.css` → preview iframe | The token cascade includes OKLCH color values; if these files were tampered to include `url(...)` references to external resources, the iframe would fetch them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Information Disclosure | `@source` paths broader than necessary | mitigate | `@source "../../../packages/ui/**/*.{ts,tsx}"` is bounded to the `@multica/ui` package; `@source "../stories/**/*.{ts,tsx}"` is bounded to the showroom's own stories. Explicitly NOT scanning `packages/core` or `packages/views` — restricted by RESEARCH §Pitfall 5 + UI-SPEC §Hard Constraint #3. Verified by automated `! grep packages/core` check in Task 2. |
| T-03-01-02 | Tampering | `@fontsource-variable/inter` substitution | accept | Catalog-pinned to `^5.2.5`; pnpm-lockfile pins exact resolved version. Mirrors `apps/desktop` which already trusts this dep. Treat as project-standard transitive risk. |
| T-03-01-03 | Tampering | `@multica/ui/styles/{tokens,base}.css` modified to load external URLs | accept | These CSS files are Phase 1 deliverables under repo control; modifications would surface in PR review. Out of Phase 3 scope (Phase 1 owns the contract). |
| T-03-01-04 | Denial of Service | `build-storybook` regression breaks Wave 2/3 | mitigate | Task 3 verify runs `build-storybook` to exit 0 BEFORE the plan completes — if it fails here, no downstream plan executes. |
| T-03-01-05 | Spoofing | Wrong `@custom-variant dark` selector → `bg-sidebar` stays white in dark mode (mismatch with `apps/web` dark resolution) | mitigate | The directive is `@custom-variant dark (&:is(.dark *))` — copied verbatim from `apps/web/app/globals.css:8` (verified by reading the file in this plan's context). Plan 02 will lock the verification gate by writing the smoke story. |
</threat_model>
