## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dev → npm registry | `pnpm install` pulls Storybook 9.1.20 + transitive deps (axe-core, vite, fontsource); supply-chain risk |
| repo → CI | `turbo build-storybook` runs the Storybook static build; if a malicious story file is added, it executes during the build |
| repo → developer machine | `storybook dev -p 6006` opens an HTTP server; if bound to all interfaces and exposed on a shared LAN, story content is reachable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-00-01 | Tampering | npm registry → catalog deps | mitigate | All Storybook 9 packages pinned to exact `9.1.20` (no `^` or `~`); Vite/fontsource use `^` because they're well-maintained and publish patch releases regularly. `pnpm install --frozen-lockfile` in CI prevents drift. |
| T-03-00-02 | Information Disclosure | `apps/showroom/package.json` published to npm | mitigate | `private: true` set; verified by automated check `cat package.json \| jq .private` returns `true`. |
| T-03-00-03 | Elevation of Privilege | Showroom imports `@multica/core` → loads API client + auth store + WS connection in dev iframe | mitigate | Plan 00 explicitly omits `@multica/core` from package.json deps; UI-SPEC §Hard Constraint #3 enforced by absence of dep. Static check `! grep -E "@multica/core" apps/showroom/package.json` in verify command. |
| T-03-00-04 | Denial of Service | `storybook dev` binds to all interfaces by default | accept | Local dev only; project standard (web/desktop dev servers also bind 0.0.0.0). No production exposure. Documented in Plan 01 README task as a future hardening item if needed. |
| T-03-00-05 | Spoofing | Wrong Storybook version installed (e.g. cached pnpm store has 9.0.x) | mitigate | Exact patch pin (`9.1.20`) in catalog; `pnpm install` will refuse mismatched lockfile entries. |
