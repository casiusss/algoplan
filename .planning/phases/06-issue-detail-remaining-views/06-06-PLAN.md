## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL ?token= → backend verify/reset | Token from email link traverses the URL bar (visible in browser history) |
| password input → backend reset | Plaintext new password crosses to backend over HTTPS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-W3-AUTH-01 | Information Disclosure | VerifyEmailPage failure branch | mitigate | Single message for reused/expired/invalid (collapsed). UI mirrors backend collapse. Per UI-SPEC §Hard Constraints #13. |
| T-06-W3-AUTH-02 | Replay / privilege escalation | VerifyEmailPage strict-mode double-fire | mitigate | useRef guard prevents firing api.verifyEmail twice on the same mount. Backend single-use enforcement is the actual safeguard, but the UI guard avoids the user seeing a confusing "already used" failure on a legit first click. |
| T-06-W3-AUTH-03 | Session hijack via brief inbox access | ResetPasswordPage success | mitigate | NO auto-login — user redirected to /auth/login + flash toast. Adversary with brief inbox access cannot walk away with a long-lived session. Per UI-SPEC §Hard Constraints #14 + Phase 5.1 Pitfall §6. |
| T-06-W3-AUTH-04 | Tampering | SignupPage 409 disclosure | accept | The 409 message IS legitimate disclosure (user opted to create account). Documented exception per UI-SPEC §Copywriting AUTH SignupPage error: "the ONE place where we must distinguish". |
| T-06-W3-AUTH-05 | Weak credential | SignupPage + ResetPasswordPage | mitigate | Submit gated on score ≥ 2 AND length ≥ 12. Backend also enforces 12-72 byte band — defense in depth. |
| T-06-W3-AUTH-06 | Tampering | ResetPasswordPage no-token branch | mitigate | Branch checks for token presence BEFORE any API call. No accidental call with empty token. |
</threat_model>
