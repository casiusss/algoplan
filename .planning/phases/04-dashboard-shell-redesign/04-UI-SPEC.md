# Phase 4 — UI Design Contract

> Visual and interaction contract for the AlgoPlan dashboard shell — sidebar, topbar, and the slot system that lets desktop inject `<DragStrip />` without duplicating layout code. Generated by gsd-ui-researcher; verified by gsd-ui-checker. Tokens, atoms, and showroom infrastructure are inherited from Phases 1–3; this contract reuses them and introduces zero new tokens.
>
> **Scope shape note.** This phase wraps every workspace page in new chrome. The "UI" surface is layered:
>
> 1. **Shell layout** — `dashboard-shell.tsx` + `app-sidebar.tsx` + `app-topbar.tsx` in `packages/views/dashboard-shell/`. Shared between `apps/web` and `apps/desktop` via slot props (`topSlot`, `searchSlot`).
> 2. **Sidebar sub-components** — Wordmark, NavSection, PriorityGrid, NotificationsBadge, DarkModeToggle, CollapseToggle.
> 3. **Topbar sub-components** — FilterChipRow, BlockerBadge, SearchInput, PrimaryCTA.
> 4. **Client state** — single `useShellStore` (Zustand) for sidebar collapsed-state; theme stays on `next-themes` (Phase 1). Selectors must return stable references.
>
> Every layer below maps to one of the four and explicitly identifies which.

## Spacing Scale

Inherits Phase 1's 8-point scale. Declared values used by this phase:

| Token | Value | Usage in Phase 4 |
|-------|-------|------------------|
| xs | 4px (`gap-1`, `p-1`) | Icon gaps inside topbar buttons; spacing between PriorityGrid cell label and count badge |
| sm | 8px (`gap-2`, `p-2`) | SidebarMenuButton internal gap (icon ↔ label); PriorityGrid 2×2 cell gap; FilterChipRow gap between chips |
| md | 16px (`gap-4`, `p-4`) | Topbar horizontal padding (`px-4`); sidebar inner padding for navigation groups |
| lg | 24px (`gap-6`, `p-6`) | Topbar height = 48px (`h-12`) so this token is **NOT** used for topbar height; reserved for any vertical breathing room between sidebar sections (`mt-6`) |
| xl | 32px | Not used in this phase |
| 2xl | 48px (`h-12`) | Topbar height; DragStrip height (matches existing `DragStrip` from `packages/views/platform/`); Sidebar header bottom padding (`pb-12` not used; sidebar header padding stays at existing `py-3` from current `app-sidebar.tsx`) |
| 3xl | 64px | Not used in this phase |

### Sidebar width contract (consumed by `useSidebar` primitive — already declared in `sidebar.tsx`)

| State | Width | Notes |
|-------|-------|-------|
| Expanded (default) | `--sidebar-width` = `256px` (existing `SIDEBAR_WIDTH_DEFAULT`) | Tracked as user-resizable between `200px` and `360px` via `SidebarRail` (existing behavior) |
| Collapsed (icon-only) | `--sidebar-width-icon` = `3rem` = `48px` (existing `SIDEBAR_WIDTH_ICON`) | Icon-only mode; labels hidden; tooltips appear on hover (existing primitive behavior) |
| Mobile (sheet) | `18rem` = `288px` (existing `SIDEBAR_WIDTH_MOBILE`) | Slide-over drawer at `<768px` (existing primitive behavior) |

**Phase 4 does NOT change these widths.** It composes the existing primitive.

### Collapse transition (consumed by `useSidebar` primitive)

The Sidebar primitive already animates the `data-state="expanded" → "collapsed"` transition via CSS (200ms ease). Phase 4 must NOT add JS-driven width animation — let the primitive own this. Any new content inside the sidebar (PriorityGrid, NotificationsBadge, DarkModeToggle) MUST hide its label via `group-data-[collapsible=icon]:hidden` when collapsed (existing pattern in `sidebar.tsx`) so the transition stays layout-shift-free.

### Topbar contract

| Aspect | Value |
|--------|-------|
| Height | `h-12` = 48px (matches existing `PageHeader` from `packages/views/layout/page-header.tsx` so existing pages keep height when wrapped) |
| Horizontal padding | `px-4` = 16px |
| Border bottom | `border-b border-border` |
| Layout | `flex items-center gap-2` — left section (filter chips), center spacer (`flex-1`), right section (search + CTA) |

Exceptions:
- DragStrip is exactly `48px` (`h-12`) — matches `packages/views/platform/drag-strip.tsx` (existing). Phase 4 reuses this component verbatim; does NOT introduce a new drag-strip variant.
- Notifications badge mini-circle is `16px` (`size-4`) — sub-touch-target, but it's purely decorative (count display); the PARENT button it sits on (`SidebarMenuButton` for the Inbox row) provides the 32px touch target.

## Typography

The shell adds NO new font sizes. Wordmark, navigation labels, filter chips, search input, and CTA all reuse the Phase 1 scale.

| Role | Tailwind class | Computed | Weight | Line height | Used by |
|------|---------------|----------|--------|-------------|---------|
| Wordmark | `text-base` | 16px | `font-semibold` (600) | `leading-tight` (1.25) | `<Wordmark>` — renders the literal string `"AlgoPlan"` |
| Body / nav label | `text-sm` | 14px | `font-medium` (500) | `leading-5` (1.43) | `SidebarMenuButton` labels (existing pattern); topbar primary CTA label; search input value |
| Caption | `text-xs` | 12px | `font-medium` (500) | default | PriorityGrid cell label (`P0`, `P1`, `P2`, `P3`); count badges; sidebar group labels (`Workspace`, `Configure`) — already `SidebarGroupLabel` default |
| Numeric badge | `text-xs` | 12px | `font-semibold` (600) | `leading-none` | NotificationsBadge count; PriorityGrid per-cell count; BlockerBadge count |

**Italic usage:** **NONE** in Phase 4. Per CONTEXT D-12 the AlgoPlan brand is Inter-only and the wordmark is set in Inter Semibold UPRIGHT (NOT italic). Italic is reserved for product display headings introduced later (Phase 5 Kanban column headers per KBN-02; Phase 6 auth titles per AUTH-01). The shell sits on every page and must remain neutral — italic on the wordmark would compete with future italic headings.

**Numerals:** Use tabular numerals (`tabular-nums`) on every count badge (NotificationsBadge, PriorityGrid counts, BlockerBadge) so the count column doesn't jitter as values change. Tailwind utility: `tabular-nums`.

**Font-family token:** `--font-sans` only. The shell never references `--font-serif` or `--font-mono`.

## Color

The shell consumes Phase 1 semantic tokens exclusively. The 60/30/10 split below describes how the *shell chrome* loads color on a typical screen.

| Role | Token | Usage in Phase 4 |
|------|-------|------------------|
| Dominant (60%) | `--background` (page canvas behind topbar; `SidebarInset` content area) | The content area inside `SidebarInset` is where consumer pages render — they paint this surface. The shell itself does NOT add background to the content area. |
| Secondary (30%) | `--sidebar` (sidebar surface), `--card` (popover content if used), `--muted` (topbar SearchInput background, FilterChip inactive background) | Sidebar always uses `bg-sidebar` (Phase 1 token); topbar background is `bg-background` (NOT `bg-sidebar` — keeps the sidebar/content distinction crisp). |
| Accent (10%) | `--brand`, `--tag-p0..p3`, `--sidebar-primary` (active nav row) | Reserved-for list below. |
| Destructive | `--destructive` (== `--tag-p0` in this palette per Phase 1 D-08) | Notifications badge color when `count > 0` — see NotificationsBadge contract. NOT used elsewhere in the shell chrome. |
| Focus ring | `--ring` | All interactive elements: `focus-visible:ring-[3px] focus-visible:ring-ring/50`. Inherits from button/input/SidebarMenuButton primitives. |

**Accent reserved for** (exhaustive — accent MUST NOT appear elsewhere):

1. **Active sidebar nav row** — `data-active:bg-sidebar-accent data-active:text-sidebar-accent-foreground` (existing pattern, unchanged). Note: `--sidebar-accent` is the *secondary* sidebar tint, NOT brand. The brand-green accent on the active row is achieved by the `--sidebar-primary` token only on dedicated active-state styling — Phase 4 keeps the existing `sidebar-accent` treatment to avoid two parallel active styles.
2. **Wordmark text color** — `text-sidebar-foreground` (NOT brand-green). The wordmark reads as identity, not as an interactive surface; coloring it brand-green would compete with active nav rows and CTA buttons.
3. **Wordmark dot mark** (optional small geometric mark left of "AlgoPlan") — `bg-brand` size `4px × 4px` (`size-1 rounded-full`). This is the ONE place in the shell chrome that paints brand-green by default.
4. **PrimaryCTA "+ New issue" button** — `bg-primary text-primary-foreground` (existing Button `default` variant). Brand-green fill.
5. **PriorityGrid cell backgrounds** — `bg-tag-p0`, `bg-tag-p1`, `bg-tag-p2`, `bg-tag-p3` (Phase 1 priority palette). The whole grid IS accent — that's its purpose.
6. **NotificationsBadge** — `bg-destructive text-destructive-foreground` when `count > 0`; HIDDEN entirely when `count === 0` (no neutral state circle).
7. **BlockerBadge** — `bg-tag-p0 text-tag-p0-foreground` (uses P0 red because blockers ARE the highest priority signal in topbar context). Hidden when `count === 0`.
8. **FilterChipRow active chip** — TagChip `color="brand"` for active state; TagChip `color={cellColor}` (e.g. `tag-p0`) for the priority-specific chips. Inactive chips render as the existing `Button` `ghost` variant (no accent).

**No hex / no RGB.** Same Phase 1 contract.

**60/30/10 verification:** Sidebar (~30%) + content canvas (~60%) + accent splashes (PriorityGrid + active row + CTA + badges, ~10%) on a typical issues page. Verify visually after implementation by sampling pixel proportions on the default issues view.
