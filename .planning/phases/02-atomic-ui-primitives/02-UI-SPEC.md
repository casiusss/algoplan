# Phase 2 — UI Design Contract

> Visual and interaction contract for the four atomic primitives (`TagChip`, `AccentBar`, `AvatarInitial`, `SegmentedControl`). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Tokens are inherited from Phase 1; this contract reuses them — it does not introduce new ones.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized in `packages/ui/components.json`) |
| Preset | `base-nova` style, Base UI variant — repo-local config; no third-party registry |
| Component library | `@base-ui/react` (NOT Radix — project-wide convention) |
| Icon library | `lucide-react` (per `components.json`) |
| Font | Inter (variable, includes italic axis from Phase 1) — token `--font-sans` |
| Component file location | `packages/ui/components/ui/{name}.tsx` (one file per component) |
| Style helper | `cva` from `class-variance-authority` for variants; `cn` from `@multica/ui/lib/utils` for class merging |
| Render helper | `useRender` + `mergeProps` from `@base-ui/react` for polymorphic `render` prop (matches `badge.tsx` pattern) |
| Imports BLOCKED | `@multica/core/*`, `next/*`, `react-router-dom`, any hex color, any RGB color |

Declared values (must be multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | TagChip horizontal padding (`px-1`); AccentBar height for thin variant |
| sm | 8px | TagChip horizontal padding default (`px-2`); SegmentedControl item gap |
| md | 16px | AvatarInitial diameter — sm size; AccentBar default height |
| lg | 24px | AvatarInitial diameter — default size; SegmentedControl height |
| xl | 32px | AvatarInitial diameter — lg size |
| 2xl | 48px | (not used in this phase) |
| 3xl | 64px | (not used in this phase) |

Border radius (inherits Phase 1 `--radius` = `0.625rem`):

| Component | Radius |
|-----------|--------|
| TagChip | `rounded-md` (`calc(var(--radius) * 0.8)` ≈ 8px) — softer than Badge's pill `rounded-4xl` to read as "tag" not "badge" |
| AccentBar | `rounded-sm` (`calc(var(--radius) * 0.6)` ≈ 6px) on outer corners; sharp on internal segment dividers |
| AvatarInitial | `rounded-full` (perfect circle) |
| SegmentedControl outer | `rounded-lg` (`var(--radius)` = 10px) — matches existing `ToggleGroup` |
| SegmentedControl items | inherit; first/last items round their outer corners only (matches `toggle-group.tsx` pattern) |

- AvatarInitial has three fixed sizes (`sm`/`default`/`lg` = 24/32/40 px) to match the existing `avatar.tsx` size contract — keeps AvatarInitial visually swappable with `Avatar` + `AvatarFallback`.
- SegmentedControl item min-width: 32px (touch target) — derived from existing `Toggle` `min-w-8`.

## Color

All four components consume Phase 1 semantic tokens exclusively. Dominant/secondary/accent split below describes the color *load* each component places on a typical surface, not new tokens.

| Role | Token | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `--background`, `--card` | SegmentedControl unselected state surface; AvatarInitial border (`after:border-border`) |
| Secondary (30%) | `--muted`, `--secondary`, `--border` | SegmentedControl track background; SegmentedControl unselected text (`text-muted-foreground`) |
| Accent (10%) | `--brand`, `--tag-p0..p3` | TagChip fill (semantic via `color` prop); AccentBar fill; AvatarInitial deterministic fill (palette below); SegmentedControl active item state (`bg-background` over `bg-muted` track) |
| Destructive | `--destructive` | NOT used directly by these atoms — `tag-p0` already maps to the destructive hue when needed (Phase 1 D-08); destructive semantics surface only at action level |
| Focus ring | `--ring` | All four — `focus-visible:ring-[3px] focus-visible:ring-ring/50` (matches existing toggle/badge pattern) |

**Accent reserved for:**
- TagChip — only when `color` prop is set (no default tag color allowed)
- AccentBar — entire body of the bar; semantic accent IS the component
- AvatarInitial — circle fill, deterministically picked from the palette below
- SegmentedControl — active item lift only (`bg-background` over track); unselected items remain neutral

**TagChip color contract (discriminated union, type-safe):**

```typescript
type TagChipColor = "tag-p0" | "tag-p1" | "tag-p2" | "tag-p3" | "brand"
```

Mapping (no other values permitted):

| Prop value | Background token | Foreground token |
|-----------|------------------|------------------|
| `tag-p0` | `bg-tag-p0` | `text-tag-p0-foreground` |
| `tag-p1` | `bg-tag-p1` | `text-tag-p1-foreground` |
| `tag-p2` | `bg-tag-p2` | `text-tag-p2-foreground` |
| `tag-p3` | `bg-tag-p3` | `text-tag-p3-foreground` |
| `brand` | `bg-brand` | `text-brand-foreground` |

**AccentBar color contract:**

```typescript
type AccentBarColor = "tag-p0" | "tag-p1" | "tag-p2" | "tag-p3" | "brand" | "muted"
```

Same mapping as TagChip plus a `muted` variant (`bg-muted`) for inactive/draft rows. No other values.

**AvatarInitial deterministic palette (8 entries, brand-safe):**

The hash function MUST be a stable, pure function of the input string (no `Math.random()`, no `Date.now()`, no `crypto.randomUUID()`). The output index MUST land in `[0, 7]`.

| Index | Background token | Foreground token |
|-------|------------------|------------------|
| 0 | `bg-tag-p0` | `text-tag-p0-foreground` |
| 1 | `bg-tag-p1` | `text-tag-p1-foreground` |
| 2 | `bg-tag-p2` | `text-tag-p2-foreground` |
| 3 | `bg-tag-p3` | `text-tag-p3-foreground` |
| 4 | `bg-brand` | `text-brand-foreground` |
| 5 | `bg-secondary` | `text-secondary-foreground` |
| 6 | `bg-muted` | `text-muted-foreground` |
| 7 | `bg-accent` | `text-accent-foreground` |

Hash algorithm (REQUIRED): djb2 string hash (`hash = 5381; for (c of name) hash = ((hash << 5) + hash) + c.charCodeAt(0)`), then `Math.abs(hash) % 8`. Document the choice inline in the source. Test must assert determinism: same input across 100 calls → same index.

## Copywriting Contract

These atoms are typography-light — they render data, not copy. The contract below covers the few user-facing strings these components own.

| Element | Copy |
|---------|------|
| Primary CTA | (none — atoms are not CTAs) |
| Empty state heading | (none — atoms are leaf renderers; empty handling lives at the consuming view) |
| Empty state body | (none) |
| Error state | (none) |
| Destructive confirmation | (none — no destructive actions in this phase) |
| TagChip remove-button `aria-label` | `"Remove tag"` (English; the visible chip label is data) |
| AvatarInitial fallback when `name` is empty | Render `"?"` initials, palette index `0`. Component MUST NOT throw on empty/null/whitespace-only names. |
| AvatarInitial `aria-label` | When `name` is provided, set `aria-label={name}`. When empty, set `aria-label="Unknown user"`. |
| SegmentedControl `aria-label` | Required prop on the root (no default) — caller passes context (e.g. `"Issue priority"`, `"View mode"`). |

**Language:** English source-of-truth. Existing app strings are bilingual de/en — these atom-level strings are short, structural, and stay English (matches `Avatar`, `Badge`, `Toggle` patterns in the codebase, which carry no translatable strings).

**Internationalization seam:** None of these strings need to be runtime-translated for v1. If translation becomes necessary, the consumer can pass `aria-label` overrides — no change to the atom contract.

## Component-Specific Interaction Contracts

### 1. TagChip

| Behavior | Contract |
|----------|----------|
| Base element | `<span>` (non-interactive by default); switches to `<button>` only when `onRemove` provided |
| Required props | `color: TagChipColor`, `children: ReactNode` |
| Optional props | `onRemove?: () => void` — when set, renders an `X` icon (lucide `X`, `size-3`) at inline-end with `aria-label="Remove tag"` |
| Polymorphism | Supports Base UI `render` prop pattern (matches `badge.tsx`) so callers can render as `<a>` for link-style chips |
| Hover state | Subtle darkening (`hover:opacity-90`) only when interactive (`onRemove` present or `render` is anchor) |
| Focus state | `focus-visible:ring-[3px] focus-visible:ring-ring/50` on the remove-button only — the chip body is non-focusable |
| Disabled state | NOT supported in v1 — chips represent assignments, not actions |
| Padding | `px-2 py-0.5` default; `px-1.5 pr-1` when `onRemove` is set (tighter to fit X) |
| Height | `h-5` (20px) — matches existing `Badge` for visual consistency |

### 2. AccentBar

| Behavior | Contract |
|----------|----------|
| Base element | `<div role="presentation">` (purely decorative — no semantics, no focus, no interaction) |
| Required props | `color: AccentBarColor` |
| Optional props | `orientation?: "horizontal" \| "vertical"` (default `"horizontal"`); `segments?: 1 \| 2 \| 3 \| 4` (default `1`) — when >1, splits the bar into equal-width segments rendered as a child array; `colors?: AccentBarColor[]` — when `segments > 1`, takes precedence over `color` and provides per-segment colors (length must equal `segments`, validated via TypeScript tuple) |
| Default thickness | Horizontal: `h-1` (4px); Vertical: `w-1` (4px) — overrideable via `className` |
| Default length | `w-full` (horizontal) / `h-full` (vertical) — fills the container |
| Rounded ends | `rounded-sm` on outer corners; segment dividers are square (no internal radius) |
| Multi-segment gap | `0` between segments (segments touch — visual reads as one bar of mixed colors, not separated chips) |
| ARIA | `role="presentation"` + `aria-hidden="true"` (decorative; does not introduce list semantics) |

### 3. AvatarInitial

| Behavior | Contract |
|----------|----------|
| Base element | `<span>` containing the initials text (does NOT use Base UI `Avatar.Root` — this is a pure deterministic-color atom, complementary to `Avatar`/`AvatarFallback`) |
| Required props | `name: string` (used for both initials extraction and color hash) |
| Optional props | `size?: "sm" \| "default" \| "lg"` (default `"default"` = 32px, matching `avatar.tsx`); `hashKey?: string` — overrides hash input when caller wants to color by stable ID instead of changeable name |
| Initials extraction | Take first letter of first word + first letter of last word, uppercase. Single-word names → first letter only. Empty/whitespace → `"?"`. Maximum 2 letters. Strip non-alphanumeric leading characters. Pure function — testable in isolation. |
| Sizes | `sm`: `size-6` (24px) + `text-xs`; `default`: `size-8` (32px) + `text-sm`; `lg`: `size-10` (40px) + `text-base`. Matches `avatar.tsx` size contract for visual swap-ability. |
| Border | Same `after:` ring trick as `avatar.tsx` (`after:border after:border-border after:mix-blend-darken dark:after:mix-blend-lighten`) for consistent edge in both modes |
| Color rendering | Tailwind background + foreground utility classes from the deterministic palette table above. Component MUST NOT use inline `style={{ backgroundColor }}` — all colors flow through tokens. |
| Determinism guarantee | Same `name` (or `hashKey` if provided) MUST produce the same palette index across renders, sessions, and processes. Test asserts this with 100-iteration loop and a known fixture (e.g. `"Stephan"` → index 5). |
| Tooltip | NOT included in this atom — wrapping in a Base UI `Tooltip` is the consumer's job. Atom stays leaf. |
| ARIA | `role="img"` + `aria-label` per the Copywriting Contract. |

### 4. SegmentedControl

| Behavior | Contract |
|----------|----------|
| Base primitive | `@base-ui/react/toggle-group` — Base UI's ToggleGroup with `toggleMultiple={false}` (single-select). This gives WAI-ARIA radiogroup semantics + roving tabindex + arrow-key navigation built-in. Same primitive as existing `toggle-group.tsx`, but composed into a single-select segmented control with distinct visual contract (track + lift, not separate buttons). |
| Why ToggleGroup over Tabs | Tabs are coupled to a panel (TabsContent); SegmentedControl is a value picker with no panel. ToggleGroup with `toggleMultiple={false}` is the semantically correct primitive. (Confirmed: existing `toggle-group.tsx` already wraps this primitive with the right Base UI imports.) |
| Required props | `value: string`, `onValueChange: (value: string) => void`, `aria-label: string`, `children: ReactNode` (one or more `<SegmentedControlItem>` children) |
| Item props | `value: string`, `children: ReactNode`, `disabled?: boolean` |
| Keyboard contract | ArrowLeft/ArrowRight cycle items (Base UI default for ToggleGroup `orientation="horizontal"`); Home jumps to first; End jumps to last; Tab moves focus OUT of the control (single tab stop, roving tabindex inside); Space/Enter activates focused item. **Tested via `@testing-library/user-event`.** |
| ARIA | `aria-label` on root (REQUIRED prop); each item gets `aria-pressed` from Base UI; active item additionally gets `data-state="on"`. |
| Track surface | `bg-muted` (matches `TabsList` default variant) with `p-[3px]` inner padding |
| Active item | `bg-background` + `text-foreground` + `shadow-sm` (lifts from track) — same active treatment as `TabsTrigger` default variant |
| Inactive item | `bg-transparent` + `text-muted-foreground` + `hover:text-foreground` |
| Item height | `h-6` inside `p-[3px]` track → 30px total — denser than ToggleGroup's `h-8` for use in headers and toolbars |
| Item padding | `px-3` for label-only items; `px-2` for icon-only items |
| Disabled item | `opacity-50 pointer-events-none` (matches existing toggle pattern) |
| Width | `w-fit` by default; consumer can pass `className="w-full"` for stretch (then items become `flex-1`) |
| Focus | `focus-visible:ring-[3px] focus-visible:ring-ring/50` on the focused item, NOT the root (roving focus model) |
| Phase 5 consumer | Issues view `Board / List` toggle — verifies labels-only path |
| Phase 6 consumer | Issue detail Priority `P0 / P1 / P2 / P3` — verifies dense 4-item path |

## Light + Dark Mode Verification

All four components inherit dark-mode behavior from Phase 1 tokens — there is no component-level dark-mode logic. The verification gate is:

1. Render each component in a `<div>` and a `<div className="dark">` ancestor.
2. Snapshot-compare visual output (Vitest test asserts presence of token-class names, not pixel snapshots).
3. Confirm zero usage of `dark:bg-*` / `dark:text-*` overrides inside these atoms — all theme adaptation is via the tokens themselves.

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none — these four components are repo-original (NOT installed via `pnpm ui:add`); they live alongside shadcn-installed components and follow the same conventions | not required |
| third-party | none declared | not applicable |

Rationale: TagChip, AccentBar, AvatarInitial, and SegmentedControl are bespoke to AlgoPlan. They cannot be replaced by `pnpm ui:add` because no shadcn block matches their semantics (color-locked discriminated union for chips; deterministic-hash avatar; single-select segmented value picker over a track). They MUST be hand-authored in `packages/ui/components/ui/` following the existing file conventions (`badge.tsx`, `toggle.tsx`, `toggle-group.tsx`, `avatar.tsx` as templates).
